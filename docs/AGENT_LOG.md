- Ported the unmerged codex/i1-recovery-20261021-143752 region-merge algorithm into main's `BulkGeometry::build_cancellable_with_stats` as reference only (no merge/rebase/cherry-pick; branch untouched). Coplanar, edge-connected faces sharing material, color and orientation merge into one face per region with real holes kept as inner loops; interior edges are removed exactly like the old pairwise diagonals (explicit source edges still cannot restore them) and unmerged coplanar seams stay soft/smooth. Opposite-winding pairs are never merged or deduplicated (intentional double-sided surfaces).
- Exact duplicate faces (same raw ring order after rotation-invariant canonicalization, same holes, same material) are removed only when coplanar cleanup is on, and the count is reported in the import summary (new `ImportReport::duplicates_removed`, summary grid row); regions that cannot produce a valid planar face fall back to the old pairwise join per region and are counted in notes. Dedup keys use raw winding because post-normalization rings would erase the orientation distinction.
- Deviation from the reference branch, driven by the required tests and measurements: the branch's hard 1,024-face region cap is replaced by breadth-first region growth capped at 2,048 faces with merged rings capped at 256 corners (oversized regions split deterministically at BFS midpoints). The 1,024 cap would have split the required 2,000-triangle wall into two faces; 2,048 keeps it one face (130-corner ring) while still splitting the 4,200-triangle strip test. The ring cap bounds local edit latency: the kernel's confined-chord cavity fast path (used by the 16 ms interactive budget) required ring ≤ 64, so merged faces always took the slow exterior-walk path (21-106 ms measured); the fast path now accepts rings up to the merge cap, its convexity check being exact and linear, and regions grow BFS-compact instead of edge-key stripes so merged faces stay convex.
- Guards unchanged: cooperative cancellation (now also checked per region/split), 1M item / 3M edge caps, input ring-work budget, never-panic fuzz batch; region work is bounded (all steps linear; 64M step budget falls back to pairwise). Tests added: 2,000-triangle wall → 1 face, window hole kept, material boundaries separate, steep curve not flattened, locally-coplanar curve falls back pairwise, exact duplicate removed / opposite-winding kept, oversized strip splits deterministically (byte-identical rebuild), cancellation mid-merge, 10-case malformed-mesh batch (build only, overlaps preserved), area equivalence before/after on four fixtures, Push/Pull moves a merged 12-edge wall as one face with working undo/redo.
- Release benchmarks (Ryzen 5 2400G): glTF 100k import incl. append **5.707 s → 1.245 s**; parse+convert 3.609 s → 1.127 s; connected chord edit 0.212 ms → 2.003 ms (budget 16 ms); app edit + dirty CPU mesh 2.123 ms → 2.909 ms. Face counts: 100k sheet ~50,000 pairwise quads → 67-68 merged faces; real textured cube fixture 12 triangles/18 edges → 6 faces/12 edges.
- Updated docs/IMPORT_PIPELINE.md (region semantics, caps, hole handling, duplicate rule, measurement table). Limits: merged faces with holes never take the convex-chord fast path (unchanged for authored holes); duplicate removal is off when coplanar cleanup is off (SKP path unchanged); the flat loose-append path re-runs cleanup, so duplicate counts can accumulate across stages. codex/i1-recovery-20261021-143752 is now fully superseded (algorithm ported, tests exceeded); left in place.
